# ops: 朝の合図

毎朝、寄付の前に「今日の注文」を出す。ルールは売買ルール（2026-10-01 ユーザー決定）で、予測モデルは使わない。

- 未保有の朝: 寄付・成行で100口買う。約定したら「約定価格 × 1.02」（呼値で切り上げ）に全口の売り指値を置く
- 保有中の朝: 「平均取得価格 × 1.02」の売り指値を全口に置いておく
- 保有中で、前日終値が平均取得価格の96%以下、かつ300口未満の朝: 寄指（寄付のみ）で100口を買い増す。指値は売り指値より1呼値安くする。
  寄付が売り指値以上なら売りが約定して、買い増しは約定しない（それがルールどおり）。買い増しが約定したら、売り指値を新しい平均取得価格 × 1.02 に置き直す
- 損切りと保有期限はない。含み損が限界（66万円）の8割を超えたら警告を出す

合図どおりに売買すると、バックテストのシミュレータと同じ取引になることをテストで確かめている（`tests/test_morning_signal.py`）。
設定は `semi2644/config/config.yaml` の `ops` 節と、`v2` 節の `position_*`・`fixed_loss_limit_jpy`。

## 準備（PC で1回だけ）

1. リポジトリを最新にする（`git pull`）。`c:/2644.T/.venv` に今の依存（pandas・yfinance・exchange_calendars など）が入っていること
2. 呼値を確かめる: 証券会社の発注画面で 2644 の呼値の単位を見て、`ops.tick_jpy`（既定 1円）を直す
3. 約定記録を作る: `ops/fills.example.csv` を `ops/fills.csv` にコピーし、例の2行を消す（ヘッダーとコメントは残す）。すでに持っている分があれば書く
4. 手で1回動かす:

   ```bat
   c:\2644.T\ops\run_morning.bat
   ```

   2644.T の日足を Yahoo から取り直して合図を作り、メモ帳で `ops/signals/latest.md` を開く。
5. タスクスケジューラに登録する（平日 8:30。PC にログオンしているときに動く）:

   ```bat
   schtasks /Create /TN "2644 morning signal" /TR "\"c:\2644.T\ops\run_morning.bat\"" /SC WEEKLY /D MON,TUE,WED,THU,FRI /ST 08:30
   ```

   休場日（祝日など）は「今日は東証の休場日。注文はなし。」と出る。

## 毎朝

1. 8:30 に開くメモ帳の「今日の注文」どおりに、9:00 の寄付の前に注文する
2. 約定したら `ops/fills.csv` に1行ずつ書く（`date,side,units,price`。同じ日の約定は起きた順。価格は約定した実際の円）
   - 寄付で買った日は、約定価格を見てすぐ売り指値を置く（合図の「前日終値なら ○円」は目安）
3. 書き忘れると、次の朝の保有状態と注文がずれる。合図の「保有」の行が証券口座と一致しているか毎朝見る

## 合図を出さないとき

- **データが古い**: 前営業日の値が取れていない（Yahoo の遅れ・通信の失敗）。少し待って `run_morning.bat` を動かし直す
- **建てた後に分割がある**: `corporate_actions.yaml` の分割日が建てた日より後。`ops/fills.csv` の分割前の行を分割に合わせて直す（口数 × 比率、価格 ÷ 比率）

## 注意

- 上限300口では、トレンドなしの架空の値動きで5年以内に含み損が66万円を超える割合が約75%（`research/trial_log/2026-10-01_operation_rule.md`）
- 配当はルールにも損益にも入れていない
- `ops/fills.csv` と `ops/signals/` は個人の売買記録なので git に入れない（`.gitignore`）
- 本ツールは情報提供であり投資助言ではない
